# Working Preferences

## Code Style

- Keep code **clean and readable** — no specific linter or formatter enforced, but follow the conventions already present in the file being edited.
- Prefer minimal changes: solve the problem without unnecessary refactors or added abstractions.
- Python is the primary language; match existing style (docstrings, inline comments where non-obvious).

## Communication Style

| Situation | Preferred style |
|-----------|----------------|
| Simple / routine tasks | Concise — short answers, minimal explanation |
| Stuck on a problem / debugging | Detailed — explain reasoning, explore alternatives |
| Code suggestions | Inline with explanation of trade-offs |

## AI Working Preferences

- **Proactively suggest improvements** — if a better approach is spotted while working, flag it.
- Don't ask unnecessary follow-up questions — use available tools to investigate before asking.
- When stuck, go deeper rather than giving up: read more files, try alternative approaches, explain what was found.
- After completing a task, offer to update the wiki if durable knowledge was gained.

## What "Done" Looks Like

- Code runs without errors.
- The change is minimal and targeted — no unrelated cleanup.
- For new features: briefly confirm what was done and why it works.
- For bugs: explain the root cause, not just the fix.
